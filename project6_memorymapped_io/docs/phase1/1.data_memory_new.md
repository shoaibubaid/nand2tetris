# 1. Build a reliable memory system.

changes that needs to be incorporated:

1. The data memory is currently sitting inside the cpu but we want it well defined but outside
2. we want multi cycle memory system where the memory operation can be expected to take more than one cycle.
3. Byte enable handling where we can access a specific byte instead of the whole word line from the ram and also 
4. error handling and memory integrity


we'll replace the old data_memory.v with a multi-cycle memory controller that sits outside the CPU and interfaces with your existing ram4k_32 hierarchy.

This version will support:
- LB, LBU, LH, LHU, LW
- SB, SH, SW
- Read-modify-write for partial stores.
- Address-range and alignment checks.
- A ready handshake for multi-cycle transactions.
- An access_error output for invalid requests.


essentially this data memory is supposed to become the new memory controller when we implement this one on the FPGA
